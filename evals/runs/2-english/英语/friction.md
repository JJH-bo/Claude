# 摩擦报告 · 英语（第 2 轮验收）

扮演老师写了五节实时黑板课（`en-rel` `en-subj` `en-agree` `en-long` `en-nonfin`）和一段课堂（`class.class.json`，上的是 en-rel）。下面每题一节，最后是「只能再加三样」。

## en-rel　非限制性定语从句

**理想的教法**
- 两句只差逗号的对比句并排放，学生**点先行词**（brother / the students），页面从关系词画一条弧线连过去；没逗号的那句，弧线把「一群里的一个」圈出来，有逗号的那句只是旁边挂一个括号注释。学生看出「挑出」和「补充」的区别，是看图看出来的，不是读解析读出来的。
- 学生自己用一句话说出逗号的作用（页面判要点，不只是存下来）。
- 题 (1) 填 who，题 (2) 把 that 改成 which，再在新句子里自己选，最后两句并一句（重点是 which 已经当宾语、后面的 it 要删掉这个错）。

**现有组件做到了哪些**
- 对比用 `quiz`（哪句暗示不止一个哥哥 / 哪句可能有学生没回家），选错了 `explain` 给原因。
- 规则用 `key` + 常驻栏；题 (1) 用 `cloze`，写了 that / which / whom 三种错答提示；题 (2) 用 `errfind`，写了 `decoys`；新句子用 `cloze`（含 `!where=` 的错答）；并句子用 `drill`，把「逗号后用 that」「which … it」写成错答提示。
- 课堂里用 `sketch` 画了「挑出一部分 / 全体」的示意，用 `mark phrase=` 划出第二句的从句。

**想做但做不到的**
- **点关系词、再点它修饰的先行词，页面判、画弧线**：做不到。`parse` 只能标「范围 + 成分」，不能表达「这个从句修饰哪个名词」；`errfind` 只能点一个词。只好用 quiz 文字选项代替，学生没真正在句子上动手。
- **圈出逗号**：最想圈的就是那两个逗号，但 `mark` 的 `word=` / `phrase=` 说的是「英文词」，标点能不能当目标没写。我只好划从句本身。
- **用一句话说出规律、页面判要点**：实时黑板里 `conjecture` 默认 `grade: off`，只记录。要等我读黑板现状才知道学生说没说到「挑出 vs 补充」。
- **删词式的改错**：`My bike, which I bought it last week` 这种「多了一个 it」的错，`errfind` 能点出 it，但 `fix:` 要写「改成什么」，没说过删掉怎么写（`fix:` 空着是「只要求点出来」，不是「删掉」）。只能挪到 `drill` 里让学生整句重写。
- 并句子的 `drill` 是整句精确比对：`Mr. Li … ` 两种主从安排我都列了，但学生只要换个语序（把从句放到别处、加 also）就会被判错，而这些写法语法上都对。

**拿不准、只能猜的**
- 英语组件（`cloze` `errfind` `parse` `chunk` `drill`）和 `quiz` 的例子里都**没有 `id:`**，第五节又要求会作答的组件都写 `id:`。我都写了，不知道这几个组件认不认 `id:` 字段（会不会当成未知字段报错）。
- `cloze` 错答提示（`!that=…`）里能不能出现 `|`、`=`、`]`、`;`、全角冒号、括号，没写。我都避开了 `|` `=` `]` `;`，但提示里有中文括号和冒号。
- `errfind` 的 `decoys:` 用 `;` 隔开，提示里不能有 `;`；`fix:` 里 `a | !b=…` 和普通答案混写的顺序有没有要求，没写。
- 选择式空 `{{[…]}}` 能不能有两个 `*`（两个都对）没写；所以「限制性用 who / that 都行」这种空我只能写成打字空。

## en-subj　虚拟语气（和过去相反、混合虚拟）

**理想的教法**
- 一条**时间轴**：学生把「条件」「结果」两张卡片分别拖到「过去 / 现在」，页面判对错；放好以后，页面在卡片下面自动亮出对应的形式（过去 → had done / would have done，现在 → did / would do）。混合虚拟就是两张卡片落在不同的格子里，学生一眼看到为什么主句是 would be。
- 一张「虚拟形式表」让学生**自己填**（现在 / 过去两行 × if 从句 / 主句两列），页面逐格判。
- 题 (2) 之后学生用一句话说出理由，页面按要点（条件在过去 / 结果在现在 / now）判。

**现有组件做到了哪些**
- 对比用 `quiz`；规则用 Markdown 表格 + 常驻栏。
- 题 (2) 的时间分析用 `steps` 的 `choices`（条件在过去还是现在、结果在过去还是现在），然后 `cloze` 填 would be，错答写了 would have been / will be / were。
- 理由用 `sketch` 画了一条静态时间轴 + `conjecture`（grade: off）。
- 混练用一个四空 `cloze`，含反方向的混合虚拟（条件现在、结果过去）。

**想做但做不到的**
- **拖到时间轴上、页面判**：做不到。`scene` / `predict` 能拖点，但它们是线代科目的组件（英语课堂里拿不到），而且拖的是坐标点，不是带文字的卡片，判的是向量距离。`sketch` 是静态的。
- **让学生自己填形式表**：Markdown 表格不能挖空；`cloze` 的 `text:` 是一段话，不是表格。`frames` 说表格里能写 `{{答案}}`，但它是演示组件，第 1 帧不能挖空，拿来做一张静态填表很别扭，我没敢用。
- **was / were 这种「考试口径对、日常也对」的答案**：我只能二选一，把 was 写成错答提示。想要「算对，但提示考试口径用 were」的第三档。
- **理由页面判**：同 en-rel，`conjecture` 不判。

**拿不准、只能猜的**
- `steps` 的 `choices` 用来做「先看时间」的诊断，系统说明里写「摸清学生想法的那道题不要放在 steps 里」（答错就揭开）。实时黑板里我还是放进去了，因为这两步是带着学生走流程，不是诊断。两种说法的边界不清楚。
- `sketch` 里中文 `text` 用 `small` 时大概多宽，没写；340 宽的图里放「would have been：结果也落在过去」这种长句会不会冲出去，只能猜。
- `cloze` 一空的答案带空格和否定（`had not rained`），学生写 `hadn't rained` 按说明「缩写不算错」应该能过；`would not have made` 写成 `wouldn't have made` 同样——没写清楚缩写的等价是不是对任何位置都生效。

## en-agree　主谓一致

**理想的教法**
- 学生在句子上**点主语的中心词**，页面从中心词画箭头到谓语（像批改时老师画的那根线）：neither of the answers → 点 Neither；the number of students → 点 number；a number of students → 点 students；either you or he → 点 he。点错（点了 answers、students、you）给针对的一句提示。这一下就把三条规则统一成「看中心词 / 看最近的那个」。
- 先凭语感做一遍（摸底），再一条一条讲，最后混合改错。

**现有组件做到了哪些**
- 摸底：一个四空的选择式 `cloze`，每个错项带提示。
- neither of：`quiz` 问「决定单复数的是哪个词」+ `errfind`（`decoys` 写了 parents、Neither）。
- the number / a number：`quiz` 对比意思，下一板 `key` + 三空 `cloze`。
- either…or：`quiz` + 三空 `cloze`（含 neither…nor）。
- 混合：两道 `errfind`。

**想做但做不到的**
- **点中心词 → 画到谓语的箭头**：没有「在句子里点一个词、页面判」的通用组件。`errfind` 不写 `fix:` 时只要求点出来，形式上能用，但它的界面叫「改错」，点错时说「这个词用得没错」，语义不对。`parse` 自定义成分（`roles: H=中心词`）套在 S 里面也许可行，但说明没讲自定义成分能不能嵌套、能不能出现在 `steps` 里，我没敢用，退回到 quiz 选项。
- **画主谓之间的连线**：`mark` 能圈词、能写旁注，`style=arrow` 是「从旁注指过去」，不能从一个词指到另一个词。
- 混合练习想**随机出新句**（像 `practice` 的 `type: custom` 那样换主语、换中心词），英语没有对应的程序出题；只能把句子一条条写死。

**拿不准、只能猜的**
- 摸底 `cloze` 里我在每句前写了 `(1)` `(2)`：这些括号数字算不算「词」，会不会影响 `mark word=` 的计数、判错时「从第几个词开始不对」的说法，没写。
- `cloze` 的选择空里提示写了 `either…or`（带省略号）、全角冒号，不知道会不会打断选项的解析。
- neither of + 复数名词 + 复数谓语在口语里也有人用，我按考研口径只收 is；同 en-subj，想要「口径」一档。

## en-long　长难句拆解

**理想的教法**
- 先让学生**自己找谓语**（三个动词短语里挑整句的那个），然后标主语（带着两个从句），盖住从句看主干。
- 用「还原」讲 which 和 that 的区别：把 which 还原回 promote 后面（宾语），that 拿掉后剩下的句子完整——最好是**学生自己把 which 拖回空位**。
- 一组「同位语从句 vs 定语从句」的快速辨认（同一个中心词 news / fact / suggestion 对着出）。
- 切意群、按意群翻译；最后换一句新的自己从头拆。
- 结构图：一棵（或括号式的）句子树，主干一层，两个从句挂在 the idea 下面，用箭头标出 which 修饰的是 the idea 而不是 habits。

**现有组件做到了哪些**
- `parse` 带 `steps: V | S`：第 1 步只标谓语，第 2 步标主语。
- `frames` 演示 which 的来历：the idea → which → 挪到句首、promote 后面空一格；两处 `??` 问「空出来的是什么」「去掉 that 缺不缺成分」。
- `recognize`：methods 写成「同位语从句 | 定语从句」，六个成对的句子，要写理由。
- `chunk` 带 `translate: on`。
- 迁移：新句子 `parse`，`steps: V | S | AppC RC`。

**想做但做不到的**
- **学生把 which 拖回 promote 后面的空位**：`frames` 只能看、选择题或填空；没有「在句子里拖动一个词到某个位置」的操作。
- **修饰关系的箭头**：`parse` 能标范围和成分，但不能表达「RC 修饰 the idea」（从句挂在哪个名词上）。这道题的核心就是「which 修饰 the idea，不是 habits」，现在只能写在解析里。
- **一层层展开的句子树**：`parse mode: show` 能画括号结构，但说明没讲它画出来的样子（括号？色块？会不会显示嵌套层次）；我也不知道 `show` 能不能配 `steps` 一层层揭开。
- **按意群翻译的判分**：`chunk` 的译文「页面不判」，要等我读。想要至少按要点判（「研究不支持」「励志书推崇」是否出现）。

**拿不准、只能猜的**
- `parse` 的 `answer:` 里**标点放括号里还是外**：我写的是 `…promote], [V is not supported] by research.`，逗号在括号外；`[AppC …], [RC …]]` 的逗号在两个从句之间。说明只说「句子原文就是去掉括号的部分，标点照写」，没说标点算不算点选的词。
- `parse` 里**没被括号括住的词**（`by research`）可不可以，学生是不是也不用标它？我故意没给它成分（施动者算状语还是别的，考研书说法不一），不知道页面会不会要求每个词都有成分。
- `steps: V | S` 时 `answer` 里的 S 很长（含两个从句）却不在 S 里面拆层次——「一道题只拆一层」和「一层层拆」两条怎么配合，我是猜的：第一道只拆主干，第二道才 `steps: V | S | AppC RC` 带嵌套。嵌套的成分（S 里套 AppC、RC）在 `steps` 的第 3 步才标，第 2 步标 S 时学生要不要把从句一起框进去？我假设要。
- `frames` 的 `??` 写在 `array` 前面还是后面有没有区别；格子里能不能放多词短语（我把 the idea 拆成两个格子）；`~` 前缀（绿）在英语这里没有「已完成」的意思，我拿来当「强调」用。
- `frames` 是演示组件外壳，`??` 选择题的错项会不会也被打乱、有没有「页面看出来」，没写。
- 常驻栏放整句原文是不是太长（一条两三行的要求），我放了，因为五块板都要看这句。

## en-nonfin　非谓语作状语

**理想的教法**
- 学生**从非谓语画一根线连到它的逻辑主语**（the city / he）。线连到 the city 时，页面问「城市会看吗？」——学生自己发现这里要被动。这是这一课的核心操作。
- 三步法（找主句主语 → 主动 / 被动 → 先后）做成一个小流程，每题按步走，页面判每一步。
- 改「垂悬」的句子：学生**改主句**，页面判「主句主语是不是动作的发出者」，不要求和标准答案一字不差。

**现有组件做到了哪些**
- `quiz`：「照字面是谁在看」「城市和 see 的关系」「哪句必须一先一后」。
- 题 (1)(2) 用 `cloze`，错答提示覆盖 Seeing / Having seen / To see、Finishing / Finished / Having been finished。
- 常驻栏放三步法；四空混练 `cloze`。
- `drill` 改主句（两题，几种写法用 `|` 列出来）。

**想做但做不到的**
- **连逻辑主语**：同 en-rel，没有「点 A 再点 B」的连线组件。
- **改写整句按约束判**：`drill` 是精确比对。`Walking in the street, a car hit him` 的正确改法很多（he was hit by a car / he was knocked down by a car / a car hit him while he was walking…），我只能列两三种，学生写出别的对的也会判错。想要「按条件判」：主句主语必须是 he、句首非谓语不变、谓语是被动——像线代 `answer` 的 `check:` 那样。
- **改错是一整句结构**：`errfind` 只能改一个词，垂悬修饰语改不了，只能用 `drill`。
- **按步判的流程**：`steps` 的 `do: true` 对文字答案是「自由作答，再对照」，不判；想要每一步都判（第 1 步点主语、第 2 步选主动 / 被动、第 3 步选要不要 having），只能拆成好几个 quiz。

**拿不准、只能猜的**
- `cloze` 的空在句首（`{{Seen|…}} (see) from …`）时大小写：说明说默认不管大小写，所以学生写 `seen` 也算对；考试要大写，我没开 `case: on`（开了会不会把整段的其他空也要求大小写？没写是不是按空设置）。
- `drill` 的原句本身是错句（`Walking in the street, a car hit him.`），页面会不会把它当作「题目原文」照常显示，没问题；但 `!Walked …=…` 的错答提示里我写了中文逗号，不知道会不会被当作分隔。
- 题 (2) 的 `Finishing his homework, he went out to play` 在不少语法书里算可以接受的，这里按答案只收 Having finished，用错答提示解释「要强调先后」。同 en-subj，想要「口径」一档。

## 通用

- **说明里科目列表没有英语**：第三节「科目」只列 `线代`、`数据结构`、`操作系统`、`组成原理`、`计网`；第五节说英语课「再写 `subject`」，但没说值写什么（`英语`？`en`？）。第七节「分科」列英语组件时写的是 `cloze`、`errfind`、`parse`、`drill`，漏了 `chunk`。
- **`quiz` 和英语组件的例子都没有 `id:`**，和「会作答的组件都写 id」不一致（同 en-rel）。
- **`mark` 的英语目标**：`phrase="who passed the exam#2"` 这种多词短语加 `#2` 能不能用，例子只有单词 `that#2`；target 是一段时「数的是整段的英文」，那段里 `**A.**`、`(1)` 这种标号算不算词，没写。标点（逗号）能不能标，没写——英语里最常要指的恰好是逗号、引号、连字符。
- **实时黑板一次写完 vs「结论不要早于猜想」**：这次要求把整节课提前写好，`quiz` 的 `explain`、下一块板的 `key` 都会提前露出结论。真实上课时我会等学生答完再写下一块板，这里只能靠分板。
- **一屏放不放得下**：`recognize` 六题、`cloze` 四句加长提示、`frames` 四帧，我估计一屏能放下，但没有尺子（英语句子一行多宽、`small` 字号多大）。

## 如果组件库只能再加三样

1. **「点一个词，再连到另一个词」的连线题（link）**，页面判、画弧线箭头。写法类似 `parse`：`answer: [The book]→[which] …` 或 `from: which; to: the idea`，支持多条连线和错答提示（`!habits=which 修饰的是 the idea`）。一样东西覆盖这一轮四道题的核心操作：关系词 → 先行词（en-rel、en-long）、非谓语 → 逻辑主语（en-nonfin）、中心词 → 谓语（en-agree）。现在这些都只能退成 quiz 的文字选项，学生没在句子上动手，这一层的理解也就没有作答证据。课堂里配 `figure highlight` / `mark` 指着连线讲也很自然。
2. **按条件判的整句改写（drill / errfind 的 `check:`）**：像线代 `answer` 的 `check:` 那样写约束（主语是 he、包含 which、不含 that、谓语被动、某个词删掉），并支持多词改错和删词。英语的产出题（并句、改垂悬、改语序）几乎没有唯一答案，现在精确比对会把对的判错，学生会不信任页面判分。再加一档「口径」答案（算对，附一句「考试口径用 were」），解决 was/were、neither…are、Finishing… 这类「日常对、考试不收」的情况。
3. **时间轴组件（timeline）**：一条过去 / 现在 / 将来的轴，学生把带文字的卡片（条件、结果、两个动作）拖到轴上，页面判位置，放好以后自动亮出对应形式（虚拟的 had done / would do，非谓语的 having done / doing）。虚拟语气、时态、非谓语的先后，三块都在问「这件事在什么时候、谁先谁后」，静态的 `sketch` 只能看不能动，`scene` 又不在英语的组件里。
