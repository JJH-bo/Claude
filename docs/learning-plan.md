# 计划：攻学习台的上限（学得会、学得牢）

接在 `docs/desk-plan.md` 后面。前面几轮把「记得全、看得见、改得动」做完了；这一轮做的是**让记录真的用来帮我学**：页面自己出练习、按证据判断学到哪了、老师上课心里有一张计划、有一把量「教得好不好」的尺子。

失误、备课、教材、屏幕这几样另外在做，不在这份里。

## 0. 定下来的事

- 我同意了全部六项（2026-11-02），顺序按性价比排（见第 1 节）。
- **省额度照旧是第一条规矩**：每一项先算清多花多少 token、多等多久。下面每一项都写了。
- 硬性规定不变：讲课只用 Opus 5.5 high；提示词里提到学生不用「他」「她」；`la-kit.js` 自包含；写错了要在页面上报出来。

## 1. 成本（2026-11-02 实测）

用 `buildSystem` + `fitTurns` 量的：线代、15 KB 资料包 + 示例记忆，说明本身约 92 KiB（约 3.4 万 token），第 30 轮整份约 150 KiB（约 5.5 万 token）。一节 30 轮的课输入约 100～150 万 token。

| 项 | 上课时多花 | 多等 | 开发量 |
|---|---|---|---|
| 信心标定 | 0（每条作答多几个字节；「没把握」且答对时多一轮，替代学生打字说「蒙的」） | 0 | 小 |
| 页面按证据算掌握 | 0（纯代码） | 0 | 小 |
| 页面自己跑的练习、混练 | **净省**：练习时不调用 Claude；原来一节复现课几十万 token | 0（页面马上判） | 中 |
| 教学尺子（模拟学生） | 上课时 0；跑尺子花开发会话的额度，只在改了提示词、教法时跑 | 0 | 中 |
| 课堂计划块 | 输入每轮约 110 token（0.2～0.3%）；只在判断变了时改写，平均每轮多不到 100 token 输出 | 改写那一轮多 2～4 秒（估） | 小 |
| 学生逐行推导、页面逐行判 | 0；交手写图变少还略省 | 0 | 大（只做计算型的） |

## 2. 第 1 批：信心标定 + 页面按证据算掌握

### 2.1 信心标定

- 作答组件第一次判出对错以后，组件底下出一行小字：「这题有把握吗？ 有把握 / 没把握」。点不点都行（不点就是不知道）。
- 点了记一条动作 `sure`（`detail: { sure, key }`，`key` 是报告里那道题的键 `itemKey`），进证据。
- 课堂里：「有把握」跟着下一条消息一起说（不单独调用）；「没把握」而且这题答对了，按作答一样 1.5 秒后发（红线 5：没把握按没过处理，老师要马上知道）。
- 报告里每道题多一个 `sure`（`true` / `false` / 没点）；`reportText` 写「（没把握）」。
- 两种最要紧的情况：**错了但有把握**（真误解）、**对了但没把握**（不能算过）。

### 2.2 掌握（`memory/mastery.js`，纯函数）

- 课堂里的 Claude 照旧不能宣布掌握（红线）。现在是**页面按证据算，出改动单，我点确认才写**（`mastery` 的 writers 加 `me`；改动单 `by: page`）。
- 一道题「干净」= 一次对（`first`）且没标「没把握」；「失手」= 错、想不出来、看了答案、标了没把握又错。
- 按时间顺序走一遍这一块（和块里每个知识点 `块#名字`）的题：
  - 两道不同的题干净 → 基础题过；
  - 基础题过以后，隔够 1 / 3 / 7 / 14 / 30 天又干净一道 → 复现通过（到第几档）；
  - 基础题过或复现通过以后失手 → 掉了，重新数。
- 从记忆里现有的状态出发（我确认过的、对话里的 Claude 写的），只看那以后的证据：不会把我定下的推翻成没依据的样子。
- 同一条还开着的提议内容变了就更新那一张；我点过「不要」的，同样的依据不再提。
- 门槛在 `mastery.js` 开头（`MASTERY_RULE`），首页改动单上写着按什么算的。

## 3. 第 2 批：页面自己跑的练习、混练（不调用 Claude）

- **题从哪来（零成本）**：下课写报告时，页面把这节课**页面能判分的组件**（答案、选择、练习、演示组件的猜下一步 / 写结果 / 填表、英语的四种……）连同这节课的 `let` 块抄进题库 `drills`（每条：块、知识点、哪节课哪个组件、原文、挂的错题）。以前的课首页打开时补抄一遍。对话里的 Claude 备课时也能往里写。
- **一次练习**：首页「练一练」，页面挑 6～8 道：到期的复现组挂的块 / 错题、标了「掉了」「基础题过」该复现的块、最近错过的。**混练**：不同块的题打乱、挨着的两道不同块，题目上不写是哪一章（考试时也不告诉你），做完再告诉你。
- 一次一道，页面判，`practice` 自定义题型每次换数。练习是一节 `kind: drill` 的课（`sessions/{编号}`），作答照常进证据（带块和知识点），掌握照常算。
- 做完：页面给小结（哪几道错了、像是哪种错法），按复现组出改动单（「R3 过了，下次 7 天后」/「没过」），我确认；错了的可以「带着这几道开课」，开一节课的资料包里放这几道题和我的作答。
- **只在开课时才调用 Claude**。

## 4. 第 3 批：教学尺子（`evals/teaching/`）

- 量「教得好不好」，不是量写法对不对。
- 几个模拟学生，各带一种设定好的误解（`AB=BA`、FIFO 当 LRU、next / nextval 混用、定语从句的关系词……）。老师照真的课堂说明上课（`buildSystem` 拼的、`protocol.js` 读的），学生看到的是板上的文字和话。
- 打分：页面能算的（多少轮看出误解、红线 1 / 2 / 5 有没有犯、学生动手的轮占多少、话多长）+ 一个评卷人按细则看整段记录。
- 小规模：每个误解一节、15 轮左右，只在改提示词、教法时跑。结果写在 `evals/teaching/results.md`。

## 5. 第 4 批：课堂计划块

- 老师在输出里写一个 ```` ```board plan ```` 块（不上黑板，学生看不到）：这节课要到哪、现在猜学生卡在哪种误解、拿什么来证实、下一步。最多 300 字。
- 页面只把**最新一份**放进下一轮的说明（「你上一轮的计划」），对话历史里把计划块去掉，压缩时也不丢。只在判断变了时改写（说明里这样要求）。
- 下课小结时把计划带上，对照「目标到了没有」。
- 先用第 3 批的尺子比一比有没有用；没用就关掉（`features.js` 的开关）。

## 6. 第 5 批：学生逐行推导、页面逐行判（计算型）

- `derive` 学生版（`mode: do`）：老师给出发的式子和要到的地方，学生一行一行往下写（矩阵、数、含字母的式子），每写一行页面查它和上一行是不是相等（精确计算；含字母的代几组数比）。
- 记录写「第 3 行开始不对：上一行等于……，这一行等于……」，老师不用看手写图。
- 只做能判等的；写证明照旧手写。
