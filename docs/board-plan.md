# 黑板不像对话框：预案和拍子

2026-11-03 我说：黑板现在像搬到了另一个对话框，内容在中间、一直往下滑。要的是**这个环境独有的长处**，不是为了像黑板而像；而且每一轮的花费不能比以前多很多。

## 花费在哪

课堂每调用一次 Claude，整份说明（组件手册、资料包、记忆、黑板现状、对话）都要重发，约 60～160 KB（2～6 万 token）。Claude 一轮多写几百字的输出比起来可以忽略。所以：

- **省的是调用次数**：让 Claude 一次多写一点、换来少调用一次，划算；
- 每次调用学生还要等几十秒——这本身就是「像对话框」的来源。

## 这个环境的长处

- 页面自己会算、会判、认得出常见错法（`variants`、英语的 `!x=提示`），不花 token、不用等；
- 板上每一步都能倒回去重看；
- 学生点的是哪一项，页面清清楚楚。

## 做什么

### 1. 预案（`board react`）

Claude 出题时顺手写好几种情况的下一步，学生作答以后页面当场接上，**不调用、不用等**；预案没写到的情况、学生打字说话、附图、板书、没把握，照旧调用 Claude。

````
````board react target=q-b3
right show=b4: 对。那换一组数呢？
wrong: 先看 $\beta^T\alpha$ 是几行几列。再试一次。
misread "FIFO": 你是按谁先进来换的？LRU 看的是最近一次用到的时间。
giveup: 提示：先写出 $\beta^T$ 的形状。
````
````

- 情况：`right`（答对）、`wrong`（答错）、`misread "…"`（页面认出来的错法里有这几个字）、`giveup`（想不出来、看了答案）、`done`（steps 揭开了最后一步）；多步的组件可以加 `step=3` 只管第 3 步。
- `show=b4`：同时揭开预先写好、藏着的段（`board add id=b4 hold`，学生看不到，黑板现状里写着「藏着」；`board show id=b4` 也能揭开）。
- 每一条只用一次（第二次答错就叫 Claude）；答对了这个组件的预案全部收起。组件所在的段被改写、撤回，预案作废。`board react target=q-b3` 块里什么都不写就是撤掉。
- 用了预案的那一轮：对话里照样记下学生的作答，后面跟一条「[系统] 页面按你预写的……接了，没调用你」，Claude 下一次被调用时看得到。板顶那句话标「预写」。
- 黑板现状里每个组件下面列着还没用的预案。

纯函数在 `kit/src/class/react.js`（解析、作答归到哪种情况、这一批能不能页面自己接、刷新后重建）。

### 2. 拍子

Claude 一轮里「说一句 → 写一段 → 再说一句 → 圈一下 → ……」时，页面一拍一拍地播：板顶只显示当前这一拍的话，这一拍写的段淡入、滚到屏幕中间，后面的段、标注、让图动先不出现；学生点「下一拍」往下走，点「‹」倒回去重看前面哪句话指的是哪儿（只是看，不撤回板上的东西）。

- 一拍 = 一段话 + 后面跟着的指令；开头的指令算第一拍；后面只有话、没有指令的并进前一拍。少于两拍照旧。
- 段（new / add / replace / pin）照常马上画（写错了马上要重写），只是先藏着；hide、mark、unmark、figure 到了那一拍才执行。
- 学生作答、说话、点「继续」，或者 Claude 要被调用之前，剩下的拍子一下子播完：Claude 被调用时黑板总是完整的。快捷回答「继续」在还有拍子时只走下一拍，不调用。
- 播的时候，这一拍的段亮、别的段淡；播到最后一拍全都恢复。
- 说明里鼓励原地改：「把第 3 行换成……」「圈出这一项」「让矩阵动一下」排在「再往下写一段」前面。

纯函数在 `kit/src/class/beats.js`。

- 点着问（长按板上一项「为什么 / 没看懂」，问题带着精确的位置）；推导每一步预写一句藏着的「为什么」。
- 旧账上板（这一块以前的错答原文摆出来）。
- ~~固定画面的板：不做~~ → 改成了第 4 节的「版面」。Claude 看不到页面，定死一块面会频繁放不下、要它重写（每次一整轮调用）；也和「按内容排板，讲透为先」冲突。重新考虑的条件：拍子用了一阵，还是觉得「在往下滑」，再做「主区固定、放不下在主区里翻页」，先量多出几次重写。
- 实时黑板（对话里的 Claude 写板）暂时不接预案和拍子：那边每一轮本来就不调用页面里的 Claude。

### 4. 版面：Claude 自己排板（2026-11-03 后来加的）

我说黑板还是从上往下一条、左右全空着，像对话框；不要模板，要课堂 Claude 根据内容排。试过一版「12×8 的格子、写坐标」：Claude 排得出来，但要它估高度，估错了页面补救（加长、加宽、缩小），而且格子允许任意交错，容易「本来从上往下读，眼睛跳到右边」。改成**说结构**：

- `board new … cols=7/5` 分栏，每段 `col=`，同一栏从上往下接，`col=all` 横跨整块板；页面按真实内容排，栏间一道竖线（一栏从上往下读，左右是两件事）。
- 段和组件都不框，靠留白分开；「下面还有」去掉；底部的条和黑板一样宽。
- 两栏差得太多（2026-11-03 真课里：左栏几行、右栏一大段英文往下长，滑下去左边空着、右边像看书）：页面量两栏的实际高度，长的那栏超出一屏、又比短的长很多时，这一层改成一栏（先左栏、再右栏，不画竖线），黑板现状里告诉 Claude；说明里也要它分栏只给两边都短、差不多高的东西。
- 边写边显示：写完一段先上板，核验不是 Opus 5.5 时整轮撤掉。
- 每轮真实等多久记下来（「⋯」里看），排版是不是让我多等，上几节真课看数。
- 验证：子代理扮课堂 Claude 上了线代 5 轮、408（LRU）3 轮，按 iPad 一屏一屏截图检查。
